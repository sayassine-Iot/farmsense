# FarmSense — Smart Farm Monitoring System (Phase 1)

Interactive Farm Overview dashboard for mixed farms in North Africa, built on
**simulated demo data**. No backend, hardware integration or credentials are
required.

> Every value shown is generated by the demo backend (`src/api/mock`). The UI
> labels this with a persistent **DEMO MODE — SIMULATED DATA** banner.

## Run

```bash
npm install
npm run dev        # http://localhost:5173  (preview roles: ?role=viewer | worker | manager | owner)
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
npm test           # Vitest: calculations, data integrity, API/access rules
npm run lint       # includes architecture boundary rules
npm run typecheck
```

## Architecture

The code follows the six-layer FarmSense architecture. See
**[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** for the layer-by-layer
mapping, the boundary rules and the Phase 2 REST mapping.

```
src/
  app/                 Layer 1  — shell, pages, overview view model, CSV export
  components/          Layer 1  — presentation only
  api/                 Layer 2  — FarmSenseApi contract (one interface per module), session/permissions
    mock/              Layers 2–6 simulated: access checks, alert rules (3D), seeded data (5A/5B, 6)
  modules/
    water-crop/        3A — water volumes, irrigation zones, field moisture
    livestock/         3B — species-specific livestock indicators
    devices/           3C — connectivity, freshness, reading quality
    alerts-analytics/  3D — alert workflow, cost estimates
  types/               access (2) · operational (5A) · telemetry (5B) · alerts-analytics (3D)
  config/ i18n/ utils/ tests/
```

- **One source of truth.** `buildOverview()` (`src/app/overview-model.ts`)
  derives every KPI, chart series and table row from one snapshot, so totals
  reconcile (water KPI = chart buckets = zone volumes = irrigation runs;
  costs = metered volume/energy × tariff; device/animal/alert counts = records).
- **Missing data is never zero.** Readings carry a quality (`ok`, `stale`,
  `offline`, `invalid`, `missing`); comparisons need covering history.
- **Thresholds are per field** (crop × soil), not global.
- **Swapping in the real backend:** implement `FarmSenseApi` over HTTP and
  select it in `src/api/index.ts`. ESLint prevents UI code from importing the
  demo backend directly.

## Configuration

`src/config/app.ts` — offline/stale rules, alert thresholds, default tariff
(EUR, editable in the UI), supported currencies, display units, species and the
metrics each species' hardware supports (pigs are intentionally unsupported).
